# 营养算法说明

本文档说明 `utils/nutrition.js` 与 `utils/recipeService.js` 中的计算逻辑与依据。

## 1. BMR 基础代谢（Mifflin-St Jeor）

学术界公认精度较高、适用于普通人群的估算公式：

```
男性：BMR = 10 × 体重(kg) + 6.25 × 身高(cm) − 5 × 年龄 + 5
女性：BMR = 10 × 体重(kg) + 6.25 × 身高(cm) − 5 × 年龄 − 161
```

## 2. TDEE 每日总消耗

```
TDEE = BMR × 活动系数
```

活动系数依据「每周运动次数」映射：

| 每周运动 | 系数 | 描述 |
|---------|------|------|
| 0 | 1.200 | 久坐 |
| 1 | 1.300 | 轻度 |
| 2 | 1.375 | 轻度 |
| 3 | 1.465 | 中度 |
| 4 | 1.550 | 中度 |
| 5 | 1.635 | 高度 |
| 6 | 1.725 | 高度 |
| 7 | 1.800 | 运动员 |

## 3. 每日推荐摄入热量

| 目标 | 调整 | 说明 |
|------|------|------|
| 增肌 | `× 1.12` | 温和热量盈余，利于肌肉合成 |
| 减脂 | `× 0.82` | 适度热量缺口，兼顾基础代谢 |
| 维持 | `× 1.00` | 保持体重 |

**安全下限**：`推荐摄入 = max(调整值, BMR)`，避免过度节食伤害代谢。

## 4. 三大营养素配比

| 目标 | 蛋白质 | 脂肪 | 碳水 |
|------|--------|------|------|
| 增肌 | 2.0 g/kg 体重 | 占总热量 25% | 剩余热量 |
| 减脂 | 2.2 g/kg 体重 | 占总热量 25% | 剩余热量 |
| 维持 | 1.6 g/kg 体重 | 占总热量 30% | 剩余热量 |

换算：蛋白质 / 碳水 = 4 kcal/g，脂肪 = 9 kcal/g。

```
碳水(g) = (摄入热量 − 蛋白×4 − 脂肪×9) / 4
```

## 5. 三餐 + 加餐 分配

| 餐次 | 占比 |
|------|------|
| 早餐 | 25% |
| 午餐 | 35% |
| 晚餐 | 30% |
| 加餐 | 10% |

## 6. BMI 与饮水

- `BMI = 体重 / 身高(m)²`；分级：<18.5 偏瘦 / 18.5–24 正常 / 24–28 偏胖 / ≥28 肥胖
- 饮水建议：`体重(kg) × 35 ml`

## 7. 食谱营养计算

```
某食材营养 = 该食材每100g营养 × (用量克数 / 100)
食谱总营养 = Σ 各食材营养
```

剂量为「个/根」等自然单位的食材，通过 `data/foods.js` 的 `UNIT_GRAM` 折算为克。

## 8. 智能食材替换算法

**目标**：替换后热量与营养基本持平，且符合场景（增肌偏高蛋白、减脂偏低脂）。

1. **同类替换**：仅在相同 `category`（主食/蛋白/蔬菜/蛋/豆/乳/水果/坚果）内选择，保证营养结构相近。
2. **等热量折算**：新食材用量按等热量重新计算
   ```
   新用量(g) = 原每100g热量 × 原用量 / 新每100g热量
   ```
3. **评分排序**：
   ```
   score = 100 − 热量偏差% × 1.6 − |蛋白质差| × 1.2
         + 场景加成（增肌 +蛋白，减脂 −脂肪）
   ```
4. **达标过滤**：热量偏差超过 **12%** 视为不达标（测试中断言保证）。
5. 返回 Top 6 候选，并附「替换理由」。

替换后通过 `applySubstitution` 生成新食谱对象（不污染原始数据），营养即时重算。
